## 项目定位:
Proactive Social-evolve Agent
### Motivation:
当前的self-evolve agent架构往往只强调如何从过往trace中总结经验-->书读百遍其意自现。
但trace的来源都是被动的,自己试错的, 没有主动学习,没有别人的经验。
我们希望让agent自发地询问获取人类经验，通过人类回答获得举一反三能力-->类比传道授业解惑。

### Keyword:  
Social-evolve 社会进化（能够询问别人的智能体，通过非参数方法（如skill等方式）优化）
Proactive 主动（自行挑选query，主动提问/探索, 有针对性、有意识地“补短”）
Efficient 有效（相比于自进化架构，有针对性的提问将实现更少样本学习，降低token消耗）
Transferable 可迁移（agent在知识/skill层面进行自进化，学习总结的是能泛化的、抽象出来的rule/insight，而非具体某些细节,具备跨benchmark的能力提升）

### 定位：
对标Agent层面工作(Openclaw/Hermes Agent) 
不是对标GEPA等优化算法：因为仅仅优化一个文本不能实现举一反三, 得评测有skill加持的agent能力上升了。项目中可以调GEPA,比如问了问题之后怎么优化skill

## 项目方案: 

### 评测问题:
World Model：CLEVRER【ICLR 2020 Oral cite707】视频问答VQA，描述性、解释性、预测性、反事实问题； PBench [NVIDIA 2025.6] 模型需要根据输入的图像/视频和文本提示，判断某个物理场景或预测是否成立; Cosmos-Reason1【NVIDIA 2025.3】评估模型的物理常识推理和具身推理方面问题
Math:  LiveBench-Math	实时更新的数学题目，防止预训练数据污染。
Code:  SWE-bench	修复真实开源仓库中的 Bug，涉及大规模代码理解。
（Idea from zqb: 对于math,先过一遍问题，失败的案例找出来，告诉他对应的知识点，再测试


### 技术框图: 

1. 基于Claude Code Agent进行
2. 给定一个问题到CC Agent, CC Agent自行回答，回复答案+自信度
3. 设置评估门限，门限包括自信度、迭代次数、token用量，如果自信度高 or 迭代次数多 or token用量多，就认为问题回答结束
4. 进入评估阶段，如果回答错误就触发主动提问阶段，如果回答正确，就判断总结skill门槛
4.1 主动提问阶段：
将问题和回答发给人类，询问人类觉得解答问题的重要知识点。把知识点作为新输入跳转第二步。
4.2 总结skill门槛：
如果出现任何一个情况，就进行skill的总结：
（1）初始回答错误，在人类帮助下回答成功；
（2）过程中工具调用超过3次；
（3）过程中出现错误，但自行修正成功
5. 总结skill阶段：如果触发了skill总结门槛，就把问题、回答、知识点、工具调用等信息进行总结，形成一个skill，保存到skill库中。注意这里要总结能够举一反三地可用信息，而不是具体细节知识点


### 技术细节及优化方向：
1. 什么时机问：当前知识不足--发现surprise-->结合JEPA
2. 问什么：因为不可能什么都问，只问那些值得问的/对自我提升最有效的；问人类,以判断正误或选择题的形式,会不会没有这个问题
3. 怎么利用好回答：不假定回答就是ground truth，或者说就算是ground truth，如果我不能从中学到有价值的东西（他说的举一反三），也是白搭
目标:
可学习进化：随着轮数上升,指标性能提升
Social交互更高效：指标性能提升效率大于自动优化方法；token效率和交互轮次效率
可泛化性强：少量样本上学习即可实现指标提升；同类型不同benchmark、不同基座模型之间、不同任务（如编程python语言和C语言)之间具有可迁移性
安装简单：整个项目包装成skill/plugin，适配不同的agent架构，下载即用
